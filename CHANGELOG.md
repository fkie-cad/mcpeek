# Changelog

## 1.1.0 (2026-10-19)

- `sessions --quick` lists every top-level transcript without parsing it: session id, cwd and first timestamp from its first records, last timestamp read from the end of the file (at most 8 MiB from each end, lines over 1 MiB skipped), file size and mtime, and the number of sub-agent sidecars and spilled results (names in its companion folder only). Newest activity first; `--limit N` keeps the N most recent. It reads no MCP log or `--debug` file and follows the same symlink and containment rules as the other commands.
- Global options `--session ID` (the session id `sessions --quick` shows, the transcript file name, or a prefix of at least 4 characters) and `--project P` (encoded project folder name, project path, or folder-name prefix), both repeatable, restrict every command to the selected sessions. An ambiguous value is a usage error that lists the candidates; a value that matches nothing is a usage error that points to `sessions --quick` (`--session`) or lists the project folders (`--project`). Only the selected transcripts and their sub-agent and spilled-result folders are parsed.
- Under a filter MCPeek shows the MCP-log files in which a selected session appears (the leading `--continue` record counts with the session that follows it) and the `--debug` files named after a selected session or paired with its records. Calls of other sessions in these files and their session-bound events are left out and counted per file; server process events are kept. Log files of concurrent sessions that lie within the debug pairing window are read for the pairing only; their rows and records are not shown. The calls, joins, durations and cross-check of a selected session are those of an unfiltered run. `logs` lists only the records and withheld values of the selected sessions, and values from other sessions' records stay withheld, also with `--show-sensitive`. Of the transcripts not selected only the first records are read (when that read finds no cwd record because it stopped at 8 MiB or skipped a line over 1 MiB, the transcript is read for its cwd as without a filter).
- `info` shows the filter, the transcript files selected out of those found (counted by name), the log files shown and what was left out. `credentials` and `grants` list the configuration in full; `servers` lists the configured servers in full, takes the servers not in the current configuration from the log files shown, and adds each server's calls in the selected sessions and the connection attempts in those log files. JSON output carries a `filter` object (list outputs become `{"filter": ..., "<name>": [...]}`; the configuration views add `filter_applies` and `filter_note`). Without a filter the output is unchanged.

## 1.0.0 (2026-10-16)

First public release.

- Tool-call timeline in timestamp order across sessions: each `tool_use` is stitched to its `tool_result`, its session (the `sessionId` the records give; a transcript file name that differs is reported) and any sub-agent sidecar through the shared tool-use id, with nesting depth, denials and spawn rows.
- Inventory of configured MCP servers (user and project scope, with headers, `headersHelper` and the configured `oauth` object), MCP tools observed being called, permission grants (an allow rule with a wildcard in the server position, such as `mcp__*`, is listed as written with a note and not mapped to servers) and project `.mcp.json` server approvals, MCP OAuth client registrations (DCR or CIMD, token presence only) and spilled tool results (read from the CLI's spill stub). Project paths are mapped into the target root below HOME of the examined host, which is inferred or given with `--home`.
- Parsing of the per-server MCP logs and `--debug` files: connection attempts (with the remote server URL the log records, shown in `servers` and `timeline` with query values withheld by default), tool calls with logged duration and outcome (a call retried after session recovery is one call, marked as retried), elicitation and shutdown events, servers no longer configured, and a cross-check of the two logs. Log calls are joined to transcript calls and unmatched or ambiguous calls are listed as such.
- Log values that can be secrets are withheld by default (including error text and the text of records that match no known template) and listed with kind, size, SHA-256 prefix and source (`--show-sensitive` prints them). `--redact` masks credential-shaped configuration fields, server env and header values, credential-shaped command-line values and URL userinfo, query values and fragments.
- Symlinks that lead outside the target root are not followed and are reported; a second path to a file or folder that is already read is read once and reported. Malformed files are read as far as possible, with warnings that name the file and the field.
- Table and JSON output for every listing, plus a Markdown or HTML report.
- Artifact locations described in `mcpeek/data/claude_code.yml`, log formats in `docs/log-formats.md` (Claude Code CLI 2.1.226).
